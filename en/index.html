A demonstration IG that declares, as TestPlan resources and Gherkin feature files, the conformance tests for the six actors of the EU Health Data API IG (EHDS Annex II): Document Publisher, Document Access Provider (with the Document Submission Option), Document Consumer, grouped Document Publisher/Access Provider, Resource Access Provider and Resource Consumer. The IG states its requirements as capabilitystatement-expectation extensions rather than profile obligations, so every test case is traceable to the CapabilityStatement expectation it tests.

This is not an approved HL7 Europe test specification. Successful test execution does not establish conformance; this guide exists to exercise the tooling. The guide publishes actor-scoped TestPlans, executable Gherkin, and a versioned synthetic fixture contract.

What is here

   
Testing Test prerequisites, fixtures, input bindings, expected results and executable Gherkin.
Method The step-by-step record of how these tests were produced and checked.
Artifacts The six TestPlan resources, one per actor, and the Gherkin scripts they name.
Downloads The published package, including the raw .feature files under tests/gherkin/.

One test plan per actor of the EU Health Data API. The IG states its requirements as SHALL/SHOULD expectations on its CapabilityStatements, so each test names the expectation it tests:

  • Document Publisher Test Plan — the publisher authenticates, finds the patient and publishes a conformant DocumentReference with embedded content (Gherkin)
  • Document Access Provider Test Plan — the server enforces SMART Backend Services, answers document search and retrieval, and where claimed accepts and refuses submissions correctly (Gherkin)
  • Document Consumer Test Plan — the consumer authenticates, looks the patient up, and searches and retrieves documents with the transactions the IG names (Gherkin)
  • Grouped Document Publisher/Access Provider Test Plan — the server exposes document search and retrieval behind SMART Backend Services (Gherkin)
  • Resource Access Provider Test Plan — the server enforces authorization and answers patient and search-by-patient requests for each resource type it offers (Gherkin)
  • Resource Consumer Test Plan — the consumer authenticates, finds the patient and searches resources by patient (Gherkin)

All are written for the Interoperability Test Bed in the OTB Gherkin language (generation 2).
